# 智枢AI — AI模型配置与电脑端/APK端功能核查报告

**核查日期**：2026-08-24
**核查对象**：生产环境（150.109.60.130）+ 本地代码
**核查目标**：AI 模型的配置是否全部正确？电脑端和 APK 端所有功能能否正常使用、是否满足该功能应有的作用？

---

## 一、核心结论（摘要）

**AI 模型配置存在问题，且 APK 端 AI 功能当前不可用。**

1. **存在一处关键 Bug**：`server/src/services/user-api-key.service.ts` 的 `PROVIDER_CONFIG.tokenhub.baseUrl` 使用了错误域名 `https://tokenhub.cloud.tencent.com`（该域名 DNS 无法解析，实测 fetch 必失败）。这导致：
   - **用户永远无法保存腾讯云 API Key**（保存前强制 `testApiKey` 验证，验证必然失败返回 400）
   - 数据库无 Key → **APK 端所有 AI 功能（对话、创作、诊断、图片/视频理解）全部不可用**
2. **电脑端 AI 创作工厂可正常使用**：电脑端采用前端直调服务商 API（Key 存浏览器 localStorage），域名全部正确，不依赖后端。只要用户在电脑浏览器配置过 Key 即可用。
3. **非 AI 业务功能正常**：三种角色登录实测均成功（HTTP 200），nginx 反代 `/api` → `127.0.0.1:3001` 正常。
4. **旧模型 ID 仍然有效**：实测用旧模型 `hunyuan-2.0-instruct-20251111` 通过正确域名调用返回 200（内容 "OK"），无需担心旧模型下线。
5. **TokenHub 平台当前有 107 个可用模型**，本地升级后的新模型 ID（`hy3`、`kimi-k3`、`glm-5.2`、`hy-vision-2.0-instruct`、`vidu-image-q2` 等）在平台模型列表中全部存在，可安全升级。

---

## 二、问题详情：错误域名导致 Key 无法保存

### 2.1 根因

| 文件 | 行号 | 当前值（错误） | 应改为 |
|------|------|--------------|--------|
| `server/src/services/user-api-key.service.ts` | 51 | `https://tokenhub.cloud.tencent.com` | `https://tokenhub.tencentmaas.com` |
| `server/src/routes/hot-topics.ts` | 32 | `https://tokenhub.cloud.tencent.com` | `https://tokenhub.tencentmaas.com` |
| `server/src/routes/voice-clone.ts` | 48 | `https://tokenhub.cloud.tencent.com` | `https://tokenhub.tencentmaas.com` |
| `server/src/services/ai-models.ts` | 46 | `https://tokenhub.cloud.tencent.com` | `https://tokenhub.tencentmaas.com` |
| `server/src/services/ai-chat.service.ts` | 142 | `https://tokenhub.cloud.tencent.com` | `https://tokenhub.tencentmaas.com` |
| `scripts/tmp_orig_factory.ts` | - | `https://tokenhub.cloud.tencent.com` | `https://tokenhub.tencentmaas.com` |

**关键机制**（`server/src/routes/ai-config.ts` 第 75 行）：`POST /api/ai-config/keys` 保存 Key 前强制调用 `testApiKey(normalizedProvider, apiKey, secretKey)`，而 `testApiKey` 用 `PROVIDER_CONFIG.tokenhub.baseUrl`（错误域名）拼接 `/models` 发起验证请求 → 域名不可解析 → 永远返回 `连接失败: fetch failed` → 接口返回 400 `API Key验证失败` → **Key 永远无法写入数据库**。

### 2.2 实测证据（生产服务器执行）

| 测试项 | 结果 |
|--------|------|
| 正确域名 `https://tokenhub.tencentmaas.com/v1/models` + 有效 Key | **200**（连通） |
| 正确域名 `/v1/chat/completions` + 旧模型 `hunyuan-2.0-instruct-20251111` | **200**，回复 "OK" |
| 错误域名 `https://tokenhub.cloud.tencent.com/models` | **fetch failed**（DNS 无法解析） |
| `GET /api/ai-config/keys`（admin 登录后） | `data: []`（4 个用户均无 Key） |
| 数据库 `ApiKey` 表 | 仅 1 条孤 Key（属已删除用户，2026-07-25 创建），对当前用户无效 |
| 三角色登录 `POST /api/auth/login` | admin/agent/customer 均成功 |

## 三、电脑端 vs APK 端功能矩阵

### 3.1 电脑端（desktop-ui）

| 功能 | 状态 | 说明 |
|------|------|------|
| AI 创作工厂（文案/图片/视频等） | ✅ 正常 | 前端直调服务商 API，域名全部正确（`tokenhub.tencentmaas.com`、`dashscope.aliyuncs.com`、`ark.cn-beijing.volces.com`），Key 存 localStorage |
| API Key 配置页 | ⚠️ 部分可用 | 先写 localStorage（成功，前端直调即生效），再调后端保存（因域名 Bug 失败，被 catch 吞掉提示"已保存到本地，但服务端同步失败"） |
| 热点话题、语音克隆等后端代理功能 | ❌ 不可用 | 依赖数据库 Key + 后端错误域名，双故障 |
| 业务功能（首页/资料/客户/订单等） | ✅ 正常 | 登录与数据读写均正常 |

**电脑端结论**：核心 AI 创作功能可用（只要用户在电脑浏览器配置了 Key）；后端同步类功能不可用。

### 3.2 APK 端（apk/Expo）

| 功能 | 状态 | 说明 |
|------|------|------|
| AI 对话（企业策划助手等） | ❌ 不可用 | 走 `/api/ai-chat/*`，依赖数据库 Key，返回 400 `API Key未配置` |
| AI 创作中心 | ❌ 不可用 | 同上，依赖数据库 Key |
| AI 诊断 | ❌ 不可用 | 同上 |
| 图片/视频理解 | ❌ 不可用 | 同上 |
| 业务功能（首页/消息/获客/招聘/推荐） | ✅ 正常 | 仅 AI 相关功能受影响 |

**APK 端结论**：AI 相关功能全部不可用（因无法保存 Key + 无兜底 Key）；非 AI 业务功能正常。

### 3.3 其他路径

- `server/src/routes/ai-chat.ts` 的 `MODEL_CONFIG.tencent.baseUrl` 已是正确域名 `https://tokenhub.tencentmaas.com/v1`，`resolveApiKey` 只从数据库取用户自配 Key（无系统兜底）——**即修复保存 Bug 并让用户配置 Key 后，APK 端 AI 全链路即通**。
- `server/src/routes/hot-topics.ts`、`voice-clone.ts` 等使用错误域名的路径需一并修复。
- `server/src/services/ai-models.ts`、`ai-chat.service.ts` 中的错误域名属死代码（未被引用），但建议一并清理防复发。

## 五、修复方案

### 5.1 必做（阻塞项）

1. 将 6 处错误域名 `https://tokenhub.cloud.tencent.com` 统一改为 `https://tokenhub.tencentmaas.com`（注意 `ai-chat.ts` 已是正确域名且带 `/v1` 路径，`testApiKey` 拼接 `/models` 时实际请求 `.../v1/models`，实测返回 200 正确）。
2. 重新构建部署 `zhishuai-api`，运行 `bash scripts/verify-login.sh` 验证三种角色登录。
3. 让 admin/agent/customer 用户在电脑端「API Key 管理」页重新配置腾讯云 TokenHub Key（保存到数据库）。

### 5.2 建议（非阻塞）

4. 将本地 14 个提交中的模型 ID 升级（hy3/kimi-k3/glm-5.2 等）部署到生产，与本地开发保持一致。
5. 清理死代码中的错误域名（`ai-models.ts`、`ai-chat.service.ts`）。
6. 可选：为后端增加系统兜底 Key 配置（环境变量），避免每个用户必须自配 Key 才能用 AI 的体验问题（当前设计为"用户自行配置、无系统兜底"，属产品决策，需用户确认是否调整）。

### 5.3 修复后验证

- 电脑端：AI 创作工厂各分类生成一次，确认前端直调正常。
- APK 端：配置 Key 后实测 AI 对话、AI 创作、AI 诊断、图片理解各一次。
- 后端代理：热点话题、语音克隆各实测一次。
- 运行 `npm run verify-apk-models`（`scripts/verify-apk-models.ts`）验证新旧模型调用。

---

## 六、结论

AI 模型配置**有问题**——核心是腾讯云 TokenHub 的 `testApiKey` 验证域名写错（`tokenhub.cloud.tencent.com` 无法解析），导致任何用户都无法把 API Key 保存到数据库，进而使依赖数据库 Key 的 APK 端全部 AI 功能不可用。电脑端 AI 创作工厂因采用前端直调方案不受此 Bug 影响，只要用户在电脑浏览器配置过 Key 即可正常使用；但电脑端的热点话题、语音克隆等后端代理功能同样不可用。非 AI 业务功能（登录、数据读写）全部正常。修复 6 处错误域名并重新部署后，用户重新配置 Key 即可恢复全部 AI 功能；生产旧模型 ID 实测仍有效，新旧模型在 TokenHub 平台均可用。
