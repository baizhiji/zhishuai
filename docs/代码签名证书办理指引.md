# Windows 代码签名证书办理指引

> 目的：消除桌面安装包（exe）的 SmartScreen 蓝色警告，提升首次安装信任度。
> 适用：智枢AI 桌面版（Tauri NSIS 安装包）正式商用推广前。
> 更新日期：2026-08-26

## 一、背景与原理

当前安装包使用 **Tauri minisign 签名**（用于自动更新校验），但未做 **Authenticode 代码签名**，因此 Windows SmartScreen 会提示"已保护你的电脑"（蓝色警告）。办理商业代码签名证书后，用 `signtool` 对 exe 签名即可消除该警告。两种签名可以共存：Authenticode 负责系统信任，minisign 负责 Tauri 更新校验，互不冲突。

## 二、证书类型选择

| 类型 | 价格（约） | 信任表现 | 办理时长 | 适用 |
|------|-----------|---------|---------|------|
| **OV 代码签名** | 1000-3000 元/年 | 消除 SmartScreen 蓝警 | 3-10 个工作日 | 一般商用推荐 |
| **EV 代码签名** | 3000-6000 元/年 | 立即获得 SmartReputation，蓝警秒消 | 5-15 个工作日（需 USB Token） | 大规模分发强烈推荐 |

说明：
- OV 证书首次签名后仍需一段"信誉积累期"，部分用户可能仍看到警告，随下载量增加自动消除。
- EV 证书使用硬件令牌（USB Key）签名，信任建立最快，适合面向陌生客户的公开下载站分发。

## 三、办理渠道（任选其一）

1. **国际 CA（推荐）**：DigiCert、Sectigo（原 Comodo）、GlobalSign，可直接官网或通过国内代理商（如 金万维/天威诚信/亚洲诚信 TrustAsia）购买，支持支付宝/对公转账，有中文客服。
2. **云厂商代购**：腾讯云 SSL 证书（代码签名证书）、阿里云数字证书服务均有代码签名证书产品，可走国内流程、发票方便。
3. **微软 Azure Trusted Signing**（新式方案）：微软官方云签名服务，无需购买传统证书，按签名次数计费，与 GitHub Actions CI 集成简单，适合自动化构建管线。

## 四、所需材料

- 企业营业执照（拍照/扫描件，加盖公章）
- 经办人身份证
- 企业邮箱（用于 CA 审核邮件）、企业电话
- 对公银行账户信息（部分 CA 需验证）
- 域控邮箱或域名所有权验证（CA 会发送验证邮件/要求添加 DNS 记录）

## 五、签名实施步骤（拿到证书后）

```bash
# 1. 安装 Windows SDK 获取 signtool（或用 Azure Trusted Signing 的 signtool 云签名）
#    https://developer.microsoft.com/windows/downloads/windows-sdk/

# 2. 对 NSIS 安装包签名（在 CI/本地构建后执行）
signtool sign /fd SHA256 /tr http://timestamp.digicert.com /td SHA256 /a ^
  "zhishuai_<version>_x64-setup.exe"

# 3. 验证签名
signtool verify /pa /v "zhishuai_<version>_x64-setup.exe"
```

### CI 集成建议（GitHub Actions desktop-build）

在 `desktop-build` workflow 中增加一步：

1. 将证书（pfx）以 Base64 存入 GitHub Secrets（`CERT_BASE64`），密码存入 `CERT_PASSWORD`
2. 构建后用 `signtool sign` 签名
3. 再执行现有 `tauri signer sign`（minisign 更新签名）——两者顺序无强制要求

> 注意：`desktop/build` 流程中的文件名重命名（`智枢AI_<v>.exe` → `zhishuai_<v>_x64-setup.exe`）与签名绑定文件名，签名务必在最终文件名上执行。

- [ ] 完成 CA 审核、获取证书（pfx + 私钥，或 USB Token）
- [ ] 将证书安全存放入密钥库/Secrets（切勿提交到 git）
- [ ] 在本地验证 signtool 签名链路

- [ ] 发布新版本后人工验证：干净系统下载安装不再出现蓝警
