### 2.3 后端 API 现状

agent.ts 路由下共 10 个端点（statistics + customers CRUD + features），但存在严重问题：

**致命 BUG**: `agent.ts` 和 `agent.service.ts` 中所有 Prisma 查询使用了不存在的字段名 `agentRelation`，当前 schema.prisma 中 User 模型的正确关联字段名为 `UserAgentRelation`。这导致 `/api/agent/*` 下所有 10 个端点在运行时全部报错。

**缺失的 API 端点**:

| 缺失端点 | 对应前端页面 | 当前状态 |
|---------|------------|---------|
| GET /api/agent/usage | 用量统计 | 不存在，前端可能用 mock 数据 |
| GET /api/agent/materials | 内容中心 | 不存在，无法查看客户素材 |
| GET/POST /api/agent/api-keys | API管理 | 不存在，无法配置 API Key |
| /api/settlement | 分成结算 | 路由在 index.ts 中被注释，且 settlement.ts 文件不存在 |

### 2.4 代理商端审计结论

存在的问题:

1. agent.ts 中存在 Prisma 字段名 BUG（`agentRelation` 应为 `UserAgentRelation`），导致代理商端所有后端功能完全不可用——这是阻断性问题
2. 用量统计、内容中心、API管理、分成结算 4 个页面对应的后端 API 完全缺失
3. 分成结算功能被注释停用，但侧边栏有入口，用户点击后会看到空白或错误
4. 没有任何 loading.tsx 或 error.tsx

### 4.3 功能开关三端联动

预期链路: Admin全局开关 → Agent分配 → Customer表现

实际情况:
- Admin全局开关管理(`admin-features.ts`): 路由已注释停用，管理员无法通过 API 管理全局开关
- Agent分配: agent.ts 字段名 BUG 导致完全不可用
- Customer读取: user-features.ts 正常工作

当前唯一可用的路径是 Admin 通过 admin-agents.ts 直接操作客户的 UserFeatureSwitch，跳过了 Agent 中间层。

### 4.4 Agent 端致命 BUG 详解

文件: `server/src/routes/agent.ts` 和 `server/src/services/agent.service.ts`

Schema 中 User 模型与 Agent 的关联字段名为 `UserAgentRelation`，但 agent.ts 中所有 Prisma 查询都使用了 `agentRelation`：

```
当前 schema.prisma 定义:
  User.UserAgentRelation  UserAgentRelation?  // 客户→代理商的关联

agent.ts 中的错误写法:
  where: { agentRelation: { agentId } }  // ❌ 字段不存在

正确写法应为:
  where: { UserAgentRelation: { agentId } }  // ✅
```

影响: `/api/agent/*` 下 10 个端点全部在运行时报错，代理商端核心业务完全瘫痪。

### 4.5 缺失的关键端点

| 端点 | 影响 |
|------|------|
| /api/agent/usage | 代理商无法查看名下客户用量统计 |
| /api/agent/materials | 代理商无法查看/管理客户素材库 |
| /api/agent/api-keys | 代理商无法配置 API Key |
| /api/settlement | 分成结算功能完全不可用（路由被注释，文件不存在） |
| /api/admin/features | 全局功能开关管理不可用（路由被注释） |
