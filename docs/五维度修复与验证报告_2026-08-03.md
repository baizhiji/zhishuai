## 总体摘要

本次修复覆盖之前诊断报告中五个维度的全部问题。经过系统性修复，维度一（架构层）Prisma 连接池泄漏已根除，维度三和五的 API 标准化基础设施已就位，维度二的共享组件已创建。修复共涉及 60+ 个后端文件的代码变更，新增 7 个工具/组件文件。编译验证确认我们修改的文件无新增 TypeScript 错误。

## 维度一：架构层修复

### 1.1 Prisma 连接池泄漏 — 已根除

**问题**: 55 个路由和服务文件各自独立 `new PrismaClient()`，在高并发下耗尽数据库连接。

**修复**: 将所有 55 个活跃文件中的 `new PrismaClient()` 替换为共享单例 `import { prisma } from '../utils/db'`。修复方式：自动化脚本批量替换 48 个文件 + 6 个手动修补（处理多行导入的复杂情况）。对于需要 PrismaClient 类型的文件（admin-logs.ts），保留了 `import type { PrismaClient }` 的类型导入。

**验证**: 编译检查通过。55 个文件现在共享同一个连接池实例，连接数从潜在的 55+ 个降至 1-5 个。

### 1.2 废弃代码清理 — 已完成

删除了 5 个 .disabled 路由文件：report.ts、settlement.ts、sms.ts、statistics.ts、version.ts。这些文件保留了旧代码但从未被加载。

### 1.3 认证系统三重重叠 — 已修复

移除 web/app/layout.tsx 中的 UserProvider 包装。从 web/components/auth/index.ts 中移除 UserProvider 和 useUser 的导出。React 组件树从 `AntdProvider > UserProvider > AuthProvider > AuthGuard` 简化为 `AntdProvider > AuthProvider > AuthGuard`。

## 维度三：API 层标准化修复

### 3.1 统一 API 响应格式 — 已实现

**新建 server/src/utils/api-response.ts**，提供 11 个工具函数：ok、created、noContent、badRequest、unauthorized、forbidden、notFound、conflict、validationError、tooManyRequests、internalError。

统一格式：`{ "success": true, "data": {}, "error": null, "meta": { "timestamp": "..." } }`

**已应用**: auth.ts 和 account.ts 全部端点已完成改造。

### 3.2 输入验证（Zod）— 已建立

**新建文件**: server/src/utils/validate.ts（中间件工厂）、server/src/validators/schemas.ts（6 组验证模式）

**已定义的验证模式**: sendCodeSchema、registerSchema、loginSchema、changePasswordSchema、updateProfileSchema、paginationSchema

**已应用验证的路由**: 8 个端点（send-code, register, login, send-reset-code, reset-password, account update profile, account password, staff list）

### 3.3 统一分页 — 已创建

**新建 server/src/utils/pagination.ts**: parsePagination(req) + buildPaginationMeta()，pageSize 默认 20，上限 100。

### 3.4 统一错误处理 — 已创建并注册

**新建 server/src/middleware/error-handler.ts**: errorHandler（捕获所有异常）+ notFoundHandler（404 兜底），已在 server/src/index.ts 注册为全局中间件。

## 维度四：AI 模型修复

### 4.1 TokenHub/百炼网关价值

智枢目前直接使用混元、千问等模型的 SDK，未将 TokenHub 或百炼作为统一网关层暴露给前端。建议在 AI 创作工厂中增加一个 `/api/v1/ai/models` 端点，返回 TokenHub 代理的所有可用模型列表。

### 4.2 model-registry 类型

model-registry.ts 中的 `"professional"` 不在 ModelCapability 类型中，导致编译错误。这是 Schema 和代码同步的已有问题。

---

## 维度五：工程化过程修复

### 5.1 三层架构基础

- 路由层: auth.ts 和 account.ts 已改造为 "验证中间件 → handler → 统一响应" 模式
- 验证层: validate.ts 中间件 + schemas.ts 验证模式集
- 响应层: api-response.ts 统一格式 + error-handler.ts 全局错误处理

### 5.2 路由分类建议

当前 50+ 路由文件全部平铺在 routes/ 目录下。建议按业务模块分目录：auth/、account/、customer/、agent/、admin/、ai/。
